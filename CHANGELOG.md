# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Main window shell: sidebar (Local health and failing count, Dashboard, Issues badge, Add new, Doctor, Settings), design tokens with a dark palette, vue-router (hash history; `#/tray` stays outside the shell), and keyboard-accessible action menus with confirmation for destructive items.
- The menu-bar popover is now a non-activating floating panel that joins all Spaces and can show over full-screen apps.
- Wails v3.0.0 app scaffold (Vue 3 + TypeScript frontend), bundle ID `dev.getvisor.visor`, minimum macOS 13.
- `internal/supervisor/xmlrpc`: dependency-free XML-RPC codec for supervisord. Log tails containing ANSI colour codes, other control characters, `\r` or invalid UTF-8 decode byte-for-byte instead of failing.
- `internal/supervisor`: typed client for every supervisord RPC Visor needs (status, start/stop/restart, groups, signals, log tails, reloadConfig/add/remove, restart/shutdown) over a pluggable `Transport` (unix socket and TCP), with basic auth, per-call timeouts, and faults matchable via `errors.Is` (`ErrNotRunning`, `ErrBadName`, …, plus `ErrUnreachable` and `ErrUnauthorized`).
- `internal/supervisor/supervisortest`: test harness that runs a real supervisord in a temp dir with dummy programs, and always shuts it down (killing stuck programs) even when a test fails or panics. Integration tests cover process control, groups, signals, log tails, `reloadConfig` add/remove, and daemon restart.
- `internal/config`: read-only parser for supervisord.conf (continuation lines, `;` inline comments only after whitespace, `%(here)s` and `%(name)02d` expansion) and config discovery that finds the socket or port, credentials, include globs and pidfile. The live check now finds the socket this way.
- `internal/app` `ServerService` lists processes to the frontend (first window shows name, group and state, or an error panel). `scripts/sandbox.sh up|down|status` runs a throwaway supervisord under `/tmp/visor-sandbox` with 12 sample processes, and `task dev` now always runs against it, so development never touches the real supervisord.
- GitHub Actions CI on macOS: `go vet`, golangci-lint, `go test -race` (with a real supervisord), a check that core `internal/` packages never import Wails (`scripts/check-core-imports.sh`), and frontend typecheck, tests and build. All actions are pinned by commit SHA.
- `internal/monitor`: one poll loop (default every 2s, `Poke` to poll now) that snapshots supervisord, diffs snapshots into events (state changed, added, removed, restarted between polls, unreachable once per outage, reconnected; the first contact after starting unreachable is not a reconnect) and computes aggregate health (error on FATAL, an unexpected EXITED status or an unreachable daemon; warning on STARTING, BACKOFF or STOPPING). Subscribers never block the loop: one that falls behind gets the latest snapshot with the events it missed merged in. Survives supervisord restarts.
- `internal/issues`: turns monitor updates into issues and history. Opens FATAL, unexpected exit (including restarts between polls), crash loop (5 restarts in 10 minutes) and unreachable issues with no duplicates; FATAL and unreachable close themselves, crash loops wait for you. Stores issues and every state change as append-only JSONL (private, compacted after 90 days).
- `internal/config`: include-file inventory (programs, `[group:x]` membership, `numprocs`, `exitcodes`) and an on-disk change watcher that reports files changed, added, removed or uncertain relative to what supervisord last loaded, without calling supervisord.
- Live overview: `internal/app` now runs the monitor, issue tracker and config watcher for the app's lifetime and pushes a `visor:overview` event (server health, version, uptime, stats, configs with their processes, "up / failing / stopped for" labels, open issues) after every poll and action, plus `visor:issue-opened`. `ServerService` gains process, group, per-file and all-process start/stop/restart, signals, clear logs, check for changes, restart and shut down supervisord, and the supervisord log; `IssueService` lists, resolves and dismisses issues and returns process history. Per-config Watch toggles persist in `watch.json`. State lives in `~/Library/Application Support/Visor` (override with `VISOR_STATE_DIR`; `task dev` uses `/tmp/visor-sandbox/state`). The first window now shows configs with their processes and updates live.
- `internal/trayicon`: draws the four 44x44 menu-bar template icons (lens outline with a centre disc for OK, a half disc for warning, a badge dot for error, outline only when unknown) with anti-aliased coverage maths.
- Menu bar and Dock: a menu-bar icon that follows server health (redrawn only when health changes, including the error badge for FATAL, unexpected exits and crash loops) opens a 360×560 popover (`#/tray`) listing processes by config file with start/stop/restart, Restart all, "Check for changes" (reports what supervisord would add, change or remove; applying comes later) and "Open Visor…". Right-click shows Open Visor, Preferences…, Launch at login (disabled for now) and Quit. Closing the main window hides it and the Dock icon; Visor keeps running in the menu bar, and opening it again brings both back. Processes in the overview carry a `Status` (running, failing, stopped, other). The frontend shares one `useOverview()` composable and a small hash router.

### Changed
- The popover's config button is now "Check for changes", and its notice says nothing was applied yet.
- An open unexpected exit raises the tray to a warning (the process may be running again); a crash loop stays an error.
- An unreachable supervisord turns the tray icon red from the second failed poll in a row (when its issue opens); a single failed poll shows a warning.
- `IssueService.List` takes a `beforeID` after `beforeMs`: "Load older" pages on (opened time, ID), so issues opened in the same millisecond are neither skipped nor repeated. Issues carry a `Note` saying why Visor closed them.
- README: develop with `wails3 task dev` (sandbox supervisord); bare `wails3 dev` talks to the real one.
- When supervisord restarts a process between two polls, Visor reads why it exited from supervisord's main log (`supervisor.readLog`, new `Client.RecentExits` and `ParseExitLines`). A planned exit (e.g. `queue:work --max-time` exiting 0) opens nothing, and a crash opens an unexpected exit under every `autorestart` setting, saying how it ended: "Exited with status 1 and was restarted by supervisord" or "Was terminated by SIGSEGV and restarted by supervisord". When the log can't tell (no `logfile`, logging to syslog, or two groups with the same process name), the restart opens "Exited and was restarted by supervisord" under `autorestart=unexpected` (the default) and only counts toward a crash loop under `autorestart=true`.
- A retry while a program is still starting no longer opens an unexpected exit; FATAL and the crash loop cover programs that can't start.

### Fixed
- A crash that supervisord restarts between two polls now opens an unexpected exit (how Visor tells a crash from a planned exit is under Changed). Every restart is written to the process history.
- Your own start, stop, restart, signal and daemon actions no longer count toward crash loops or open unexpected exits for the restarts they cause, so they no longer turn the tray red; history marks those changes "by you". A program you start that exits with an unexpected code still opens an issue. After you shut supervisord down, no unreachable issue opens until it is back; after you restart it, one opens if it is not back within 30 seconds.
- A dismissed or resolved issue no longer reopens on the next launch when supervisord still shows the same failure; a new failure still opens one.
- A process removed from supervisord closes its open issues ("program removed"), and a process restarted straight into FATAL opens a FATAL issue.
- "Failing for" counts from the latest open FATAL or unexpected exit, not the oldest issue.
- The config watcher stops listing a deleted config file as removed once supervisord restarts.
- Opening Visor brings back a minimised main window.
- A failure in the same second as you dismissed or resolved an earlier one now opens an issue, instead of counting as already dismissed.
- The issue store no longer loses the record written after a line torn by a crash, and a record too large to read is skipped instead of stopping Visor from opening its issue history.
